# WSIViewer 工程化整改计划

## 目标

本计划将当前可运行的 WSIViewer 原型整理为结构清晰、可复现构建、具备可靠标注持久化和完整关键路径测试的项目。重点目标如下：

1. 将新版 Next.js 前端从 `frontend2` 正式迁移到 `frontend/wsi-viewer`，并移除嵌套 Git 仓库。
2. 修复 Docker、开发启动、依赖和 API 错误处理的不一致。
3. 将 Canvas 坐标与几何算法抽离为纯函数核心。
4. 对自由画笔和橡皮擦建立单元、属性、组件、浏览器和持久化测试。
5. 将 JSON 标注存储迁移到支持事务和并发控制的 SQLite。
6. 将测试、构建、全栈冒烟和文档检查固化为发布门禁。

## 执行原则

- 每个阶段的功能代码和测试必须同时完成，不把测试延后到最后。
- 每个已确认缺陷必须先有可复现测试，再提交修复。
- 阶段验收未通过时不进入下一阶段。
- 目录迁移、几何重构、存储迁移分别提交，避免形成不可审查的大型改动。
- 禁止长期保留无说明的跳过测试或不稳定重试。

## 阶段 3：前端目录迁移

### 目标

将新版前端统一到 `frontend/wsi-viewer`，消除 `frontend2` 和不可复现的嵌套 Git 结构。

### 工作内容

- 删除工作区中的旧 CRA 前端；历史版本由 Git 保存。
- 将 Next.js 前端迁入 `frontend/wsi-viewer`。
- 移除嵌套 `.git` 和父仓库 gitlink。
- 排除 `node_modules`、`.next`、`out`、缓存和构建产物。
- 将包名改为 `wsi-viewer-frontend`。
- 更新 Compose、开发脚本、忽略规则和文档路径。

### 测试与验收

- 全仓库不再引用 `frontend2`。
- 新前端目录由父仓库以普通文件跟踪。
- 迁移前后的路由、lint、类型检查、测试和 build 结果一致。

## 阶段 4：构建与启动链路整改

### 目标

保证开发、CI 和 Docker 使用可复现且一致的构建方式。

### 工作内容

- 固定兼容 Next.js 的 Node 版本和 Python 依赖版本。
- 将存在直接高危审计项的 Next.js 16.1.6 升级到 16.2.10，并把脚手架工具移出生产依赖。
- 为 Compose 增加本地 `build` 配置。
- 移除废弃 Compose 字段。
- 增加前后端健康检查和合理的启动依赖。
- 统一后端包导入与 `uvicorn app.main:app` 启动方式。

### 测试与验收

- 空缓存安装、`docker compose build --no-cache` 和容器重启通过。
- 本地开发模式和 Docker 模式的首页、API、DZI 路由一致。

## 阶段 5：API 客户端与状态一致性

### 目标

保证 HTTP 失败不会被当成成功，前端状态不会与后端静默分叉。

### 工作内容

- 建立统一 `fetchJson` 和结构化 `ApiError`。
- 检查所有响应状态，支持请求取消。
- 切换切片时取消旧请求。
- 标注变更失败时保留或恢复原状态，并显示可见错误。

### 测试与验收

- 覆盖成功、4xx、5xx、非 JSON、断网、超时和取消。
- 删除或更新失败时不存在幽灵标注。
- 旧切片响应不会覆盖新切片状态。

## 阶段 6：Canvas 与几何公共核心

### 目标

建立自由画笔、橡皮擦和测量共同使用的、与 React 无关的纯几何模块。

### 工作内容

- 抽离屏幕、Canvas、viewport 和图像坐标转换。
- 抽离多边形面积、方向、闭环、bounds 和合法性检查。
- 统一浮点容差、取整和 selector 序列化。
- 支持内部环和 MultiPolygon 表达。

### 测试与验收

- 覆盖不同缩放、平移、容器尺寸和各类边界坐标。
- 使用属性测试验证几何序列化往返和面积不变量。
- 公共几何模块达到 100% 行/函数覆盖，分支覆盖不低于 95%。

## 阶段 7：自由画笔完整重构

### 目标

保证每一笔自由画笔都能正确开始、预览、完成、取消、保存和恢复。

### 工作内容

- 抽离采样、路径简化、校验和 selector 生成。
- 建立 `idle → drawing → validating → saving → completed/failed/cancelled` 状态机。
- 修复 `pointercancel`、工具切换、切片切换和卸载边界。
- 防止多指混合、重复提交和无效几何。
- 明确定义自相交路径行为。

### 测试与验收

- 覆盖简化算法、重复点、非有限数值、快速和超长笔画。
- 覆盖全部 Pointer Events 生命周期和 API 失败重试。
- 浏览器中绘制后刷新，几何和位置保持一致。
- 一次笔画最多生成一个标注，取消操作绝不保存。

## 阶段 8：橡皮擦几何算法重构

### 目标

使橡皮擦对全部支持形状产生连续、确定、可回滚的结果。

### 工作内容

- 使用连续扫掠区域构建擦除轨迹。
- 支持矩形、椭圆、多边形、自由画笔、分裂片段和内部孔洞。
- 处理触边、重合边、极小碎片和退化结果。
- 建立独立交互状态机，提交期间隔离下一笔操作。
- 取消或失败时恢复整笔操作前快照。

### 测试与验收

- 覆盖未命中、局部、完全、分裂、孔洞和高速拖动。
- 每项关键几何不变量至少运行 1,000 组随机输入。
- 输出不含无效环或非有限数值，剩余面积不大于原面积。
- 相同输入始终产生相同结果。

- 一笔擦除只能全部成功或全部失败。

## 阶段 12：标注详情编辑与 GeoJSON 交付

### 目标

解决标注始终显示 `Untitled`、缺少可发现导出入口的问题，并保证连续编辑、
并发更新和跨浏览器下载不会破坏 revision 或丢失数据。

### 工作内容

- 在侧栏增加标签、备注和颜色编辑表单。
- 兼容旧版单一 `commenting` body，保留未被编辑的其他 W3C bodies。
- 将同一标注的几何、详情和删除请求串行化，并在请求执行时读取最新 revision。
- 使用 Annotorious REMOTE 更新同步服务端结果，避免保存时产生临时取消选择。
- 对 409/404、最新版刷新失败、快速连续编辑和切片切换迟到响应进行恢复。
- 选中标注后支持 `Delete`/`Backspace` 快速删除；输入区和系统组合键不拦截，
  重复按键及并行删除去重，且继续遵守 409 后再次确认的语义。
- 合并服务端分配 ID 前发生的几何编辑，并在 ID 替换后按 revision 顺序补写，
  避免新建标注的最后一次拖动静默丢失。
- 橡皮擦批处理遇到外部 revision 冲突时加载最新版；用切片 generation 隔离
  排队中、请求中以及 A→B→A 切换后的迟到结果。
- 增加可见 GeoJSON 下载按钮，导出规范化 Polygon/MultiPolygon，并保留原始
  selector 与图像像素坐标说明。
- 兼容 RECTANGLE、ELLIPSE、POLYGON、MULTIPOLYGON、旧版 SVG polygon 和
  `xywh=pixel:` FragmentSelector；遇到无效几何时终止导出并报告 annotation ID。

### 测试与验收

- 单元与组件测试覆盖 body 兼容、草稿保留、连续 revision、乱序更新、
  pending-create 编辑、橡皮擦 batch 409/404 恢复、A→B→A 迟到响应、
  Delete/Backspace 输入区保护与 in-flight 去重、全部 selector 和下载 Blob。
- 后端测试验证只更新元数据时 target 不变且 revision 递增。
- Playwright 在 Chromium、Firefox、WebKit 中验证两次连续保存、刷新恢复、
  真实 GeoJSON 下载、导出内容和选中标注快捷删除。
- ESLint、TypeScript、覆盖率门槛和 Next.js 静态生产构建全部通过。

## 阶段 13：评审问题与可复现发布加固

### 目标

关闭全项目评审中除自由画笔 `maxPoints` 外的其余确认问题，并保证构建失败不会
被误报为成功或覆盖当前可用前端。

### 工作内容

- 限制 region/thumbnail 输出尺寸和 DZI 参数，修复 `_files` 只应作为末尾协议
  后缀移除的问题，并在线程池内完成图像编码和关闭。
- 将同步 SQLite 标注操作交给 FastAPI 线程池；修复首次迁移竞态、WAL 初始化
  竞态、W3C 扩展字段丢失和 OpenSlide 关闭句柄登记残留。
- 修复物理角度计算、旧 selector 显示、初始加载/新建竞态、切片状态隔离、
  pending-create 删除和标注列表键盘可访问性。
- 收紧默认 CORS、Compose 和开发服务器监听范围；外网暴露必须显式配置。
- 将前后端镜像构建拆分为中立、可跟踪的 `build-image.sh` 和本机忽略的个人
  `build.sh`，移除废弃且会吞失败码的旧 CRA 构建器。
- 前端静态导出使用 release staging 与原子 `current` 切换；失败保留当前版本，
  成功版本保留有限历史 hash 资源。
- 修正 `lib/` 忽略规则误伤 `src/lib/` 的问题，并增加交付脚本故障注入测试。

### 测试与验收

- 后端全量、前端单元/覆盖率、类型、Lint、生产构建和三浏览器 E2E 全部通过。
- 故障注入覆盖 npm 构建失败、原子切换失败、陈旧源码、未发布目录清理、
  历史资源保留、个人/公开脚本隔离和默认回环监听。
- 自由画笔 `maxPoints` 明确不在本阶段修改范围内。
